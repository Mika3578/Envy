| D-022 | 2026-09-30 | Solo-maintainer merge policy: **one** mandatory non-author approving review (Copilot may count when enabled); thread resolution + required deterministic CI + CodeQL/Gitleaks; staged Draft validation and real x64/Win32 Release with EnvyTests during live-test and Ready; manual maintainer transitions and squash merge; `SonarCloud Code Analysis` remains required until a separate migration (see `protect-develop.desired.json`); auditable desired ruleset at `.github/rulesets/protect-develop.desired.json`. Zero-approval was rejected: PR-controlled `classify-changes` / build workflows can invent green required contexts without a non-author review. Copilot Code Review is requested **once per stable HEAD**, not on every push (`review_on_push=false`, `review_draft_pull_requests=false`). A Copilot request is a synchronization barrier: wait for a submitted review on that SHA, then evaluate a **fresh post-review snapshot**; a pre-request zero-thread snapshot is never `CLEAN`. An advisory commit status `Final review gate` binds Copilot `APPROVED` (and independent human `APPROVED` for privileged governance paths) to the **current** PR SHA and re-reads HEAD/threads/CI before publishing success; it is not a required check until after merge and observation. Auto-merge stays off. | Keep a hard trust boundary against self-bypass of merge gates while retaining staged validation. Native review-on-push spends Copilot credits on every correction push. Details: `docs/10_dev/pr-workflow.md`. | Active |
