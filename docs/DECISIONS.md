| D-008 | 2026-09-11 | Reference implementation policy: specifications first; then live interop evidence; then established clients (eMule Community, aMule); then newer architecture references (eMule Qt, eMule AI, aria2-next); experimental work (Ember, eMule eSE) last and never labelled as Kad2/eMule standard. | D-009 | 2026-09-16 | NAT/Firewall recovery is phased (P0 interface → P1 WFAS → P2 local/external ports → P3 MiniUPnPc 2.3.x vendored with absolute SSDP/HTTP timeout bounding → P4 PCP/NAT-PMP → P5 diagnostics). Keep MiniUPnPc vendored for this track; do not introduce vcpkg solely for MiniUPnPc. | Bisectable PRs; avoid conflating discovery, firewall, port model, and dependency upgrades. | Active |
| D-010 | 2026-09-17 | Targeted IGD discovery via `upnpDiscoverDevices(..., searchalltypes=1)` — one MiniUPnPc discovery receive phase for requested ST values, not 4× sequential legacy searches. `UPnPTimeout` is the per-receive delay in MiniUPnPc 2.0 (not a strict wall-clock SSDP deadline); absolute SSDP/HTTP bounding is #142 / P3. Keep only explicit IGD/WAN ST; gateway `upnp:rootdevice` fallback limited to selected gateway IP + exact LOCATION string dedupe. Call `UPNP_GetValidIGD` once on filtered candidates; never treat result 3 as WAN target. | On LANs with multiple UPnP responders, legacy sequential discovery could fetch unrelated device descriptions and significantly delay NAT setup when no usable IGD advertisement was available. | Active |
| D-011 | 2026-09-17 | Network listen sockets must not wait for NAT traversal methods to finish. Order: select interface → bind/listen → network up → async NAT → update external ports. Implemented in `CNetwork::OnRun` (#141): no `IsAsyncFindRunning` listen gate; `MapPorts` after successful listen. | Runtime showed ~45 s from "setup port mappings" to TCP/UDP listen while Method 0/1/2 ran. | Active |
| D-012 | 2026-09-18 | Long-term product platforms: Windows x64 (primary, supported), then Linux x86_64 and macOS ARM64 as **planned** (not supported until compile/test/CI evidence). Linux ARM64 / Windows ARM64 later; macOS x86_64 only if cost is reasonable. Non-targets: Linux x86-32 and macOS 32-bit. | Stop reinforcing Windows-only coupling while keeping the shipping MFC Windows client stable. Details: `docs/20_arch/PORTABILITY_PLAN.md`. | Active |
| D-013 | 2026-09-18 | New `EnvyCore`-facing interfaces must not expose MFC/Win32 types when a portable abstraction exists. No mass migration of historical `CString`/MFC/Win32 code. | Prevent new API debt during #91/#161 extraction. Windows impls may keep MFC/Win32 behind boundaries. | Active |
| D-014 | 2026-09-18 | Win32/x86 is **legacy**: keep building/testing (Stage A); evaluate dropping user releases (Stage B) only after multi-compiler 64-bit + non-Windows tests; evaluate dropping Win32 CI (Stage C) only with evidence. No removal in foundations work. | Win32 still catches 32/64 bugs; premature removal would hide defects without Linux/macOS coverage yet. | Active |
| D-015 | 2026-09-18 | CMake for the **full** MFC app stays low priority (D-002/D-004). CMake for portable `EnvyCore`/parsers/HashLib/tests/headless is a multiplatform foundation and should eventually build with MSVC, Clang, and GCC without MFC/Windows SDK. | Portable CI needs a non-VS path; converting `Envy.sln` wholesale is unnecessary risk. | Active |
| D-016 | 2026-09-18 | Bootstrap sources are data files (`DefaultServices.dat` / `DefaultServers.dat`), not C++ constants. Learned hosts stay in `HostCache.dat` / `Discovery.dat`. Do not compile replacement IP lists into the binary. Kad/ADC must not be advertised as complete because a catalogue was refreshed. | Cold-start must survive an update-server outage; IPs age faster than list-provider URLs. Details: `docs/30_protocols/bootstrap-sources.md`. | Active |
| D-017 | 2026-09-19 | Native Remote API is versioned REST `/api/v1`. Inbound host: Windows HTTP Server API (`http.sys`) on a dedicated port (default localhost). Do not extend `CRemote` GET/query RPC. Outbound Torznab: existing `CHttpRequest` + body limits. No cpp-httplib/Crow/Drogon/Boost.Beast. JSON library deferred. | Smallest stack that is real HTTP, limitable, and testable without the MFC UI. Audit: `docs/20_arch/AUDIT_REMOTE_API_2026-09.md`. | Active |
| D-018 | 2026-09-19 | First *arr download-client adapter is a **qBittorrent Web API v2 subset** on top of native Envy services. Transmission RPC is deferred.
