**BEP 27 private-torrent peer-source isolation (#317, complement to #525)** - Private torrents (`private=1` in the info dict) no longer acquire peers or trackers outside their own tracker through any remaining path: the extended handshake stops advertising `ut_pex`, incoming PEX and tracker-exchange messages are ignored (no sources or trackers added), Envy/Shareaza source exchange is neither requested, served nor accepted, local service discovery (BEP 14) announces are ignored, unsolicited DHT results never populate the source set, cross-network (G1/G2/ED2K/Kad) searches and search-hit sources are blocked, and the torrent's embedded DHT node list no longer seeds the host cache. Private multi-tracker failover drops the failed tracker's peer set before announcing to the next tracker, and applying a private torrent to an existing download (e.g. a completed magnet) drops peers found before the flag was known. Tracker addresses in logs are redacted of their announce query string, so passkeys never reach the log.
