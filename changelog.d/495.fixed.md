**ED2K file request deferral (#495)** - A transient Library lock timeout no longer answers an ED2K `FILEREQUEST` with a false `FILENOTFOUND`. The reply decision is centralized in `Envy/Ed2kFileRequestOutcome.h`: shared-and-uploadable files and active downloads answer as before, lock contention defers silently (eMule/aMule peers re-ask) with a rate-limited diagnostic distinguishing deferred busy from genuine misses, and actually missing or non-uploadable files keep the existing negative reply. Security deny/ban paths still fail closed.
